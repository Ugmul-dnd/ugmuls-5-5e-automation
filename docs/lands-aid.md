# Land’s Aid

Using the native save activity places its area and opens a two-column confirmation. The left lists visible eligible enemies inside the placed Region, selected by default; uncheck any to exclude them. The right selects exactly one eligible healing creature from the same area. Healing is limited to creatures matching the caster’s friendly disposition, including the caster and unconscious allies. It does not add the healing recipient to the save/damage target list.

Confirmation stores the selected healing descriptor on the original usage card. The existing area workflow confirms the damage targets and opens the native scaled save/damage activity. The sibling native healing activity then rolls with its own exact target and the same usage origin. It calls `rollDamage`, not `use`, so there is no second Wild Shape charge, template or usage card. Healing uses the standard native card/Apply/Undo workflow. Original damage and healing dice remain separate and native.

Canceling target confirmation uses the existing pending-cast cancellation path. Completed healing is marked to prevent duplicate followups; cancellation of the healing roll does not mark it completed. Other users’ clients cannot generate the followup. No chat-history scan or render-time mutation is added. Target candidates refresh for relevant token/actor updates while the chooser is open, and hooks are removed when it closes.

Automated tests cover left/right layout, enemy defaults and exclusion, a single heal selection, same-area eligibility, exact grouped targets, native damage-before-heal sequencing, heal-only selections, canceled confirmation/rolls and duplicate prevention. Live GM/player verification remains pending.

Land’s Aid cards default to their recorded recipients, including native target trays. Retarget appears on the primary save usage and on the separate healing result. The save control updates the usage and its exact linked damage results; damage results have no independent Retarget. healing retargeting updates only that healing card and allows one friendly recipient. Existing dice, save outcomes and HP/Undo records are preserved; applied damage results must be undone before changing save/damage targets. Applied healing does not lock the independent damage branch. Presentation refreshes use the shared queue. Pending healing retries use the recorded healing activity rather than the usage’s save activity.
