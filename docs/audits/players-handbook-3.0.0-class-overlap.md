# Player's Handbook 3.0.0 class automation review

Reviewed 2026-11-13 against the installed **dnd-players-handbook 3.0.0** compendiums and **D&D5e 6.1.0** runtime, on `dev-card-replacement`.

Requested release discussion: <https://github.com/foundryvtt/foundryvtt-premium-content/discussions/1865>. The discussion could not be fetched during this review. Release changes were read from the installed book's `phbChangelog0000` journal, page `3.0.0`, then checked against actual installed class/feature/effect records. Changelog wording alone was not treated as proof of automation.

This is an audit. No runtime automation settings, owned character items, book files, or system files were changed. Local inspection used copies of the compendium databases; generated data and inspection tooling remain Git-ignored.

Follow-up: the user confirmed Short Rest recovery on a test Bard with updated Bardic Inspiration and Font of Inspiration, with the module recovery helper disabled. At the user's request, the Font helper, import and setting have since been removed. Legacy Font recovery support is deliberately retired; no character migration is included. The table below records subsequent removals and explicit decisions to retain existing workflows.

## Compatibility strategy

1. Detect the capability on each owned item/effect/activity. Module version alone does not say whether an Actor has updated features, legacy features, or a mixture.
2. Prefer native recovery scales, conditional bonus/Advantage/minimum rules, active effects and expiry when present. Preserve fallback automation for old items.
3. Resolve moved activities by feature identity and native activity data, then evaluate level/visibility. Reuse the chosen native formulas and resources instead of hard-coding replacement dice.
4. Separate native rules from module workflow: snapshots, reaction reservations, targeting, roll preservation, pending damage, grouped cards, Apply/Undo and authority validation remain valuable.
5. Reconcile only module-owned legacy configuration. Old `fontRecovery` and `wardingFlareRecovery` snapshots must not restore an obsolete recovery array over a newly updated native feature. Preserve player changes and newer native data.

Recommended implementation order: prevent duplicate Druid Potent damage and repair Overchannel/Disciple; make Font and Flare recovery native-aware; adapt moved Flare/Cleric/Deflect/Starry activities; then review remaining native-rule and reminder overlap. Test both legacy and updated features before changing defaults.

## Verification and limits

- Read installed 3.0.0 changelog and class/feature/effect records from copied databases; no live database was opened for writing.
- Local source-audit assertions exercised actual module exports with installed feature shapes: redundant Font/Flare recovery writes, Disciple missing formula, Cleric identifier misses, Druid Potent recognition/native bonus overlap, Deflect Energy selecting no activities, and Overchannel's initial count of 20. Additional assertions checked removed Starry activation, Sear ownership and Elemental Affinity layout.
- Installed D&D5e rest code was checked: rest activity activations are included in the resulting rest chat card. This was not treated as automatic execution.
- No live Actor migration or in-game validation was performed. Source-audit assertions are not a full gameplay regression test or a full-suite pass.
- Existing successful gameplay tests in this chat do not establish compatibility with freshly replaced 3.0.0 items. Installing the book and replacing an Actor's owned feature are separate operations.
